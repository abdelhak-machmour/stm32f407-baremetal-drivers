# STM32F407 Bare-Metal Drivers

Register-level peripheral drivers for the **STM32F407VGT6** (ARM Cortex-M4F), written in C **without the STM32 HAL or LL libraries**.

Each driver is built directly on the reference manual (RM0090): peripheral register structures, base addresses, clock control and interrupt configuration (EXTI / NVIC) are all implemented by hand, then validated on hardware with dedicated test applications.

> Developed while following the *Mastering Microcontroller and Embedded Driver Development* course by FastBit Embedded Brain Academy. The code was written and tested by me on my own board, and extended beyond the course material (see the SPI EEPROM application).

## Drivers

| Driver | Features |
|---|---|
| **GPIO** | Input / output / alternate function / analog modes, speed, pull-up/pull-down, push-pull or open-drain, EXTI interrupts (rising, falling, both edges), NVIC enable and priority |
| **SPI** | Master and slave, full-duplex / half-duplex / simplex RX-only, 8/16-bit frames, CPOL/CPHA, baud-rate prescaler, software or hardware slave management, **blocking and interrupt-driven** transfers with application callbacks |
| **I2C** | Master transmit and receive, standard mode (100 kHz) and fast mode (200/400 kHz), CCR and TRISE computed from PCLK1, ACK control, repeated START |

## Hardware

- **Board:** STM32F407G-DISC1 (Discovery)
- **MCU:** STM32F407VGT6, Cortex-M4F, 1 MB Flash, 192 KB RAM
- **Peripherals used in tests:** on-board LEDs and user button, Arduino Uno (SPI / I2C slave), 25LC256 SPI EEPROM
- **Debug output:** SWO / ITM (`printf` through the SWV ITM Data Console)

## Getting started

1. Clone the repository:
   ```bash
   git clone https://github.com/abdelhak-machmour/stm32f407-baremetal-drivers.git
   ```
2. In **STM32CubeIDE**: `File > Import > General > Existing Projects into Workspace`, then select the repository folder. All projects are detected.
3. In `stm32f4xx_drivers`, only one test application can be built at a time (each one has its own `main()`): right-click the files you don't want -> `Resource Configurations > Exclude from Build`.
4. Build and flash with the on-board ST-LINK.

## Known issues and roadmap

The drivers are a learning project and are being improved. Known points:

- [x] `*_IRQInterruptConfig()`: NVIC `ISER`/`ICER` now written directly (write-1-to-act registers).
- [x] `GPIO_Init()`: `SYSCFG->EXTICR` is cleared then OR-ed, so other pins in the register are preserved.
- [x] `GPIO_IRQHandling()`: `EXTI->PR` is cleared with a direct write (rc_w1), only the handled line is cleared.
- [x] `*_IRQPriorityConfig()`: priority field is cleared before being set, input masked to 4 bits.
- [ ] `RCC_GetPCLK1Value()`: the PLL clock source is not supported yet.
- [ ] Blocking APIs wait on status flags without timeout (a missing I2C slave blocks the MCU).
- [ ] USART driver
- [ ] SPI EEPROM application: read/write sequence (in progress)
